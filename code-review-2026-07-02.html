Notch — Code Review

Full-app review: bugs, design flaws, inconsistencies, architecture. Repo at commit 9fc82ff, 2026-07-02.

Scope & method. All ~9,650 lines of Swift across app, window, state, managers, services, agent-watch, widgets, and views were reviewed by six parallel subsystem passes; the highest-severity claims were then re-verified directly against the source. The logic test suite passes: 71 tests, 0 failures.

Overall. The codebase is well above average for a project of this kind: a clean composition root, deliberate pure-core extractions with tests, careful comments explaining non-obvious decisions. The problems cluster in four places: (1) global event monitors and click-through state that trust the wrong signals, (2) lifecycle gaps in long-running integrations (media adapter stream, weather one-shot fetch, agent liveness), (3) an event pipeline that loses ordering between the Unix socket and the main actor, and (4) config-file surgery on ~/.claude/settings.json with two genuine data-loss edges.

1. High-severity bugs

HighFixedAny left-button drag opens the file-drop UI — not just file drags
Notch/Window/NotchWindowController.swift:110–160, 189–198

dragMoved() is driven by a global .leftMouseDragged monitor with no way to distinguish a file drag from a text-selection drag, window drag, or toolbar drag. Any drag passing through the generous catch area (notch width + 200pt wide, ~90pt tall) flips panel.ignoresMouseEvents = false and calls beginDropTargeting() — the panel expands onto the tray and starts intercepting mouse events mid-drag. On a non-notched display the simulated-notch fallback puts this zone over the center of the menu bar, so ordinary drags near the menu bar trip it too. The drag session needs a real file-drag signal (e.g. NSPasteboard(name: .drag) contents or deferring entirely to the SwiftUI drop delegate's validateDrop).

HighFixedMedia adapter stream death causes an EOF busy-loop and permanently stale media UI
Notch/Managers/Media/AdapterMediaController.swift:57–61

The pipe's readabilityHandler handles EOF with guard !chunk.isEmpty else { return } but never clears itself. Once the perl bridge exits or crashes, the fd stays readable-at-EOF and FileHandle re-invokes the handler continuously — a spinning dispatch queue at high CPU. There is also no terminationHandler, no restart, and no fallback to the scripting controller, so the app silently shows the last track forever. On EOF the handler should nil itself and the controller should recover or fall back.

HighFixedWeather is fetched once at launch and never refreshed
Notch/Managers/Widgets/WeatherManager.swift:27–39

start() issues a single one-shot requestLocation(); fetch runs only from didUpdateLocations and the temperature-unit sink. There is no timer, no re-fetch on panel open (WidgetGridView.onAppear refreshes only bluetooth and focus), and no cadence at all — the widget presents the launch-time temperature as current indefinitely. Compounding it, didFailWithError only logs: one transient CoreLocation failure leaves an authorized user on the placeholder permanently with no retry path.

HighFixedDisabled agent providers resurrect sessions: ingest() has no isEnabled guard
Notch/Managers/Agents/Providers/SocketAgentProvider.swift:85; ClaudeCodeProvider.swift:140

refresh() guards isEnabled in both providers, but ingest() does not, and AgentManager.route() forwards envelopes without checking. A running agent process keeps its hooks/plugin loaded after the user toggles the integration off, so its envelopes rebuild and re-publish sessions — rows and the compact pill reappear while the feature is disabled.

HighFixedKilled agent process leaves a stuck "working" pill: no liveness timer for .processPid providers
Notch/Managers/Agents/Providers/SocketAgentProvider.swift:161–188

prune() only runs inside ingest()/refresh(), and scheduleStalePrune() exits early unless liveness == .staleness. If an OpenCode/oh-my-pi process is killed mid-turn (no "ended" envelope), its busy session stays published and the compact pill shows a working agent indefinitely. Sessions whose envelopes never carried a pid (peer pid can be 0) are unprunable under .processPid and live forever.

HighFixedProject paths containing spaces break transcript lookup — live sessions flap in and out of the UI
Notch/Services/Agents/ProcessScanner.swift:84

newestTranscript encodes the cwd by replacing only / and . with -, but Claude Code also rewrites spaces (verified on this machine: ~/Library/Application Support/… is stored as -Users-…-Application-Support-…). For any project path with a space, the computed directory doesn't exist, the scan sees no transcript, and the session survives only as a hook-only entry — purged after the 30s grace window, then re-added on the next hook. The session visibly flaps.

HighFixedCollapse resets the tab mid-close, swapping visible content during the fade-out
Notch/State/NotchState.swift:155; Notch/Views/ExpandedView.swift:106–121; NotchRootView.swift:119–129

collapse() sets presentation = target and expandedTab = .home in the same animation, while isCollapsing deliberately keeps the expanded body mounted for the whole ~0.4s close. Collapsing from media/tray/agents therefore cross-fades the dying panel to WidgetGridView while it shrinks, jumps expandedSize to the home height mid-animation, and freshly mounts the widget grid (and everything its widgets kick off) on every close from a non-home tab — exactly what the NotchRootView comment says the design avoids. The tab reset should happen after the close completes (where isCollapsing is already released).

HighFixedBackup dropEntered has no matching dropExited — a missed drag-exit pins the panel open forever
Notch/Views/NotchRootView.swift:153–156

NotchDropDelegate.dropEntered calls state.beginDropTargeting() as a backup for the window controller, but the delegate implements no dropExited. If the backup path is the one that fired (the controller missed the enter, so it will also miss the exit) and the user drags away or cancels with Esc, nothing calls endDropTargeting(). isDropActive stays true and collapse() bails on guard !isDropActive: the notch is stuck expanded on the drop chooser until another successful drop cycle.

2. Security & data integrity (agent-watch)

MediumFixedSubstring marker "agent-hook" can delete unrelated user hooks from settings.json
Notch/Services/Agents/AgentConfigInstaller.swift:51, 310–319

pruneMarker removes any inner hook whose command merely contains "agent-hook", and it runs on every install (prune-then-re-add) and uninstall across all seven managed events. A user hook like ~/bin/my-agent-hook.sh is silently deleted from ~/.claude/settings.json. This is user-config data loss from a substring match; the marker should be an exact command match or a dedicated marker key.

MediumFixedstatusLine uninstall silently erases the user's original command when the snapshot file is gone
Notch/Services/Agents/AgentConfigInstaller.swift:183–186, 200–212

The user's original statusLine survives only in ~/.notch/bin/.statusline-orig.json. If that file is missing (user deleted ~/.notch while cleaning up), removeClaudeUsage sets root["statusLine"] = nil — the original command (e.g. ccstatusline) is permanently removed from settings.json. The already-installed path in installClaudeUsage has the same failure: it regenerates the wrapper with "true", silently disabling the user's status line.

MediumverifiedUnlocked read-modify-write of settings.json can drop concurrent edits
Notch/Services/Agents/AgentConfigInstaller.swift:248–273, 329–346

installHooks/removeHooks/installClaudeUsage read, mutate, and atomically rewrite the file with no lock or mtime check. Claude Code itself rewrites ~/.claude/settings.json, and ClaudeCodeProvider.start() re-runs the installer at every launch whenever claudeBridgeInstalled() is false — a write landing between read and write is silently clobbered (last-writer-wins). Related: the full-file rewrite is pretty-printed and key-sorted, so the first install also reformats the user's whole settings file.

MediumFixed (partial)Unbounded concurrent socket reads allow thread exhaustion; hook client has no connect timeout

Fixed the client half: HookClient.send connects non-blocking with a 2s poll + 2s send timeout, and the Claude hook installs with timeout: 5. Open: the server-side concurrent-read cap (thread exhaustion), an accept/read-model change.

Notch/Services/Agents/AgentSocketServer.swift:17, 133–160; Notch/App/HookClient.swift:147

Every accepted client blocks a GCD worker in read() on the concurrent ioQueue with no cap. The 2s SO_RCVTIMEO is per-read(), so a peer trickling one byte every <2s holds its slot indefinitely (the 1 MB cap bounds memory, not time); N such peers pin N threads toward the ~64-thread pool limit. Once the listen(fd, 8) backlog fills, HookClient.send blocks in connect() with no timeout — and since the Claude hook entry is installed without a timeout field, each hook can stall the user's Claude turn up to the 60s default. Same-uid trust domain, but reachable by any buggy client.

MediumFixedHook envelopes can be delivered out of order, and ingest-time timestamps make the stale one authoritative
AgentSocketServer.swift:122–127; AgentManager.swift:68–70; ClaudeCodeProvider.swift:150

Clients are read on a concurrent queue and each envelope hops to the main actor via an independent Task { @MainActor … } — two hooks fired back-to-back (separate short-lived hook processes, e.g. PostToolUse then Stop) can be processed reversed. HookSnapshot.time is stamped Date() at receipt, so the reordered older hook wins the hook.time >= fileTime rule in StatusReducer, leaving a session stuck on "Thinking" after the turn finished. For SocketAgentProvider, an "ended" processed before an earlier "busy" resurrects the session (up to 30 minutes under staleness liveness). Delivery needs a serial ordering (serial ingest queue or a sequence number).

MediumFixedDirectoryWatcher deinit tears down the FSEvents stream off the watcher queue — use-after-free race
Notch/Services/Agents/DirectoryWatcher.swift:28–36, 44, 50–54

The stream context uses Unmanaged.passUnretained(self) and the callback does takeUnretainedValue() on the watcher queue, but deinit runs on whatever thread drops the last reference and calls FSEventStreamStop/Invalidate/Release there, unsynchronized with the queue. A callback already scheduled can dereference the deallocated object. Fix: passRetained with release in a cancel path, or drain the queue synchronously in deinit.

LowverifiedSocket permission race; directory attributes are no-ops for pre-existing ~/.notch; unconditional unlink lets a second instance steal the socket
Notch/Services/Agents/AgentSocketServer.swift:36–43, 79

The socket is bound with umask permissions and only chmod(path, 0o600) afterward — a brief window of looser access. createDirectory(attributes: [.posixPermissions: 0o700]) applies the mode only on creation, so a pre-existing ~/.notch keeps whatever mode it had. Separately, unlink(path) runs unconditionally at bind, so a second app instance (dev build beside installed build) silently steals the socket while the first keeps accepting on a bound-but-unlinked fd; there is also no already-started guard, so a double start() leaks the prior source/fd.

LowverifiedClient-claimed pid overrides the kernel-verified peer pid, and it's the wrong pid anyway
AgentSocketServer.swift:146; HookClient.swift:24; AgentConfigInstaller.swift:57

The server prefers envelope.pid (client-supplied) over LOCAL_PEERPID. And because the installed hook command is /bin/sh -c '… ; exit 0' (the trailing exit 0 prevents an exec), getppid() in the hook tool returns a transient shell pid that is dead by delivery — not the agent, as HookEnvelope.pid's doc claims. Harmless for Claude/Codex today, but SocketAgentProvider's .processPid liveness does kill(pid, 0) on this trusted value: a wrong or reused pid keeps phantom sessions alive or prunes live ones.

LowTerminalJumper opens an environment-sourced URL with any scheme; dead-pid path scans the whole pid table on the main actor
Notch/Services/Agents/TerminalJumper.swift:23–26, 126–131; ProcessScanner.swift:59–63

focusURL comes from the watched process's environment (WARP_FOCUS_URL) and is passed straight to NSWorkspace.shared.open(url) with no scheme allowlist — any same-uid process matching isClaudeProcess can plant an arbitrary URL that opens on the user's click. Also, when the pid is dead, resolvePID synchronously runs cwd(of:) over every pid on the system on the main actor — thousands of syscalls, a visible UI hitch.

3. Bugs — core, window & media

MediumFixedOverlapping shares wedge the panel's key-capable state
Notch/App/AppEnvironment.swift:125–131

shareCoordinator = coordinator deallocates any in-flight coordinator while its share sheet may still be open. NSSharingService.delegate is weak (verified in the macOS SDK header), so the first share's didShareItems/didFail… callbacks are silently dropped — no crash, but that coordinator's endShareSheet() never runs, so panel.presentingShareSheet can stay latched true and the passive overlay stays permanently key-capable. share(urls:via:) needs a reentrancy guard or per-share coordinator retention.

MediumFixedClick-through region goes stale when the pill resizes under a stationary cursor
Notch/Window/NotchWindowController.swift:200–221, 231–246

updatePassthrough() is only re-run on pointer moves and presentation/HUD changes, but the hit rect depends on live content (media track, compact activity, tray items, settings). If the pill grows or shrinks while the cursor is stationary — an activity appears/expires, media starts — panel.ignoresMouseEvents keeps the old answer: a click on a newly appeared pill passes through to the window beneath, or a click beside a shrunk pill is swallowed, until the next mouse move.

MediumFixed.receive(on: RunLoop.main) defers panel ordering during event-tracking modes
Notch/Window/NotchWindowController.swift:72

The presentation/HUD sink that orders the panel in/out is scheduled on RunLoop.main, which only fires in .default mode. While the run loop is tracking (status-bar menu open, scroll momentum, window drag), a HUD or expand won't order the panel front until tracking ends. The publishers are already main-actor; drop the scheduler or use DispatchQueue.main.

MediumFixedScripting media controller runs main-actor methods and NSAppleScript on a background queue
Notch/Managers/Media/ScriptingMediaController.swift:39–73, 199–210

The class is @MainActor, yet send()/refresh() hop to a private DispatchQueue and call the isolated read(app:) there — GCD closures aren't isolation-checked under SWIFT_STRICT_CONCURRENCY: minimal, so this compiles but violates the annotation. NSAppleScript is additionally documented main-thread-only. Works today, breaks under strict concurrency, and is undefined behavior per Apple's thread-safety guidance. AdapterMediaController has the same shape: it inherits @MainActor from MediaControlling but mutates buffer on the FileHandle readability queue.

MediumFixedAdapter probe blocks the main thread at startup
Notch/Managers/Media/AdapterMediaController.swift:42; MediaManager.swift:62

MediaManager.start() runs on the main actor and AdapterMediaController.init? synchronously spawns perl and calls process.waitUntilExit() for the "test" probe. Loading the perl interpreter plus the framework check can take hundreds of milliseconds, freezing launch right after the window appears.

MediumFixedMusic "toggleRepeat" is not a toggle
Notch/Managers/Media/ScriptingMediaController.swift:192

For Music the command unconditionally runs set song repeat to one, so once pressed the user can never turn repeat off (or reach "all") from the notch, while Spotify genuinely toggles. Two backends behind the same MediaCommand.toggleRepeat behave differently.

MediumFixedBrightness HUD can display the previous volume value
Notch/Managers/HUDManager.swift:56–66; Notch/Services/Brightness.swift:33

On a brightness key, kind = .brightness; show() fires immediately and value updates 50ms later — and only if brightness.current() succeeds. DisplayServicesGetBrightness(CGMainDisplayID(), …) fails when the main display is external (or the private symbol is missing), so the HUD renders the last volume level (e.g. 0.75) under a brightness glyph, every time.

MediumFixedsetNowPlaying bypasses publish(), so starting music never surfaces the notch from hidden
Notch/Managers/ActivityManager.swift:103–111

Every other activity goes through publish(), which calls state.showCompact(); setNowPlaying calls replaceOrInsert directly. When playback starts while the notch is hidden, the now-playing sliver doesn't appear until some unrelated activity fires. It also skips the lastEventID/TTL bookkeeping — a second mutation path in a class designed around one.

MediumFixedTrayManager blocks the item-provider callback ~3s per file for no reason
Notch/Managers/TrayManager.swift:60, 193–210

The comment justifies the synchronous semaphore.wait(timeout: .now() + 3) because "the drag URL dies when the handler returns" — but makeThumbnail reads item.url(relativeTo: root), the already-persisted copy, not the drag temp URL. The wait only delays the shelf entry and the "Added to Shelf" peek by up to 3 seconds per file and blocks NSItemProvider's queue. Thumbnailing can be fully async after the copy.

MediumFixedposition(asOf:) reports 0:00 for unknown-duration tracks
Notch/Model/MediaModels.swift:29

guard isPlaying, duration > 0 else { return min(elapsed, duration) } — the doc says duration is "0 if unknown", but for such tracks (live streams, some adapters) min(elapsed, 0) is 0 whether paused or playing. Elapsed time is discarded exactly when it's the only signal available.

MediumFixedmediaremote-adapter enablement instructions point at the wrong target
project.yml:87–92

The commented dependencies: - package: mediaremote-adapter block sits under the notch-hook tool target, not the Notch app. Following the README/comment instruction links the adapter into the Foundation-only CLI while the app's #if canImport(MediaRemoteAdapter) stays false — the opt-in feature silently never activates.

LowAssorted low-severity core/media items
various

• Paused Music beats playing Spotify — refresh(preferred: nil) walks [music, spotify] and takes the first non-stopped app, so a paused Music track wins over actively playing Spotify at launch (ScriptingMediaController.swift:47–74).

• Artwork failures never retried — lastArtworkIdentity is set before the fetch; an error leaves the track permanently artless (ScriptingMediaController.swift:78–91).

• Tray TTL and share staging only pruned at launch — for an app that runs for weeks, trayTTLDays is effectively ignored mid-session and ShareStaging copies accumulate on disk (TrayManager.swift:33–36, 140–153).

• Synchronous disk I/O in view accessors — thumbnail(for:) does Data(contentsOf:) + decode on the main actor per shelf item during layout (TrayManager.swift:124–132); persist() likewise writes pretty-printed JSON synchronously on every add/remove, contradicting Persistence.swift's "only touched from background contexts" comment.

• SystemDefinedTap / BatteryManager teardown traps — both hold Unmanaged.passUnretained(self) in C callbacks with no invalidation path; safe only because AppEnvironment owns them for app lifetime (SystemDefinedTap.swift:29–56, BatteryManager.swift:26–43). HUDManager's comment that "the tap can't be torn down cleanly" is wrong — CGEvent.tapEnable + CFMachPortInvalidate exist.

• Fixed clockString has no hour component — a 90-minute item renders "90:00" (Extensions.swift:39–45).

• Settings opened via private stringly-typed selectors — Selector(("showSettingsWindow:")) silently no-ops if macOS renames it; the supported openSettings action exists at this deployment target (AppDelegate.swift:89–91).

• NSScreen() fallback yields degenerate geometry — a zero frame during display reconfiguration, and the simulated-notch path draws over the menu bar of non-notched displays (ScreenGeometry.swift:73).

• Main-thread-only AppKit call in nonisolated deinit — NSEvent.removeMonitor in NotchWindowController.deinit (52–54).

4. Bugs — widgets

MediumFixedBattery: first power source assumed internal; desktop Macs show a fake permanent "100%"
Notch/Managers/Widgets/BatteryManager.swift:52–71

refresh() takes the first entry of IOPSCopyPowerSourcesList with a break // internal battery is the first source and never checks kIOPSTypeKey, so a UPS can be read as the Mac's battery. On a desktop with no battery the list is empty, percent stays at its initial 100, and the battery tile renders a permanent fake 100%.

MediumFixedCalendar data never advances with time — ended events linger, the horizon is frozen at launch
Notch/Managers/Widgets/CalendarManager.swift:49–63

reload() builds its predicate with withStart: now, but nothing time-driven ever re-runs it — no timer, no day-change observer, and WidgetGridView.onAppear doesn't touch calendar. Hours after the last .EKEventStoreChanged, finished meetings still occupy the widget's rows, isInProgress styling is computed against a stale list, and events beyond the launch-time 7-day/25-item window never surface.

MediumFixedWeather forecast decode can crash on a malformed API response
Notch/Managers/Widgets/WeatherManager.swift:130–139

Indices are derived only from daily.time, then used to subscript weather_code, temperature_2m_max, and temperature_2m_min. If Open-Meteo ever returns a shorter parallel array (partial data, API change), that's an out-of-bounds crash on untrusted network input. The same fetch path also parses API dates with a DateFormatter lacking en_US_POSIX and a timezone: a non-Gregorian system calendar parses "2026-07-02" wrong, and location-vs-device timezone differences can shift day labels by one (127–131).

MediumFixedLaunch-time permission prompts stack, contradicting the app's own no-stacking rule
WeatherManager.swift:29; FocusManager.swift:23; CalendarManager comment

CalendarManager.start() deliberately defers its TCC prompt ("that stacks dialogs on top of the location prompt and feels like a freeze"), yet WeatherManager.start() and FocusManager.start() both prompt unconditionally at launch — two dialogs can still stack on first run. The weather prompt fires even when showWeatherWidget is false, since all managers start unconditionally in AppEnvironment.start().

MediumFixedFocus tile confidently shows "Off" when authorization was never granted
Notch/Views/Widgets/FocusWidgetView.swift:22; FocusManager.swift

The view renders focus.isOn ? "On" : "Off" without reading focus.authorized; when access is denied or undetermined, refresh() bails and the tile displays "Off" for an unknown state. Calendar and Weather both grew an "Enable" affordance for this case; Focus has none, so it can't be fixed from the UI.

5. Bugs — agent-watch pipeline

MediumFixedEnabling "Watch coding agents" at runtime is a silent no-op
Notch/Managers/Agents/AgentManager.swift:34–35; SettingsView.swift:44, 65, 78

start() runs once from AppEnvironment.start() behind guard settings.agentsEnabled; the Settings toggle binds straight to the setting and never calls agents.start(). Turning the feature on later builds no providers and no socket server — the "Coding agents" section renders with zero rows and the per-agent toggles no-op. The footer only warns that turning it off needs a relaunch.

MediumFixedhookCwd grows unbounded — one leaked entry per Claude session
Notch/Managers/Agents/Providers/ClaudeCodeProvider.swift:142; SessionReconciler.swift:58

Every envelope with a cwd writes hookCwd[sid], but SessionEnd clears only hookState[sid]. The reconciler derives expiredHookIDs by iterating hookState.keys, so a sid whose hookState is already gone can never be expired — hookCwd accumulates every session ever seen until relaunch. Related: a hook-only sid that arrives without a cwd leaves a permanent hookState entry that is skipped by both the surface and expiry branches (SessionReconciler.swift:60).

MediumFixedIn-flight reconcile survives disable(); liveness loop can keep scanning while disabled
ClaudeCodeProvider.swift:72–83, 174–186

stop() cancels the tracked tasks, but the unstructured Task { await self?.reconcile() } from beginWatching()/refresh() is untracked, reconcileGeneration isn't bumped on stop, and neither reconcile() nor rebuild() checks isEnabled. Disabling during a scan publishes scanned sessions after onSessions([]), and a busy session re-arms the 8s liveness recheck while the integration is off.

MediumFixedisIdleNotification substring heuristic can suppress genuine permission prompts
Notch/Services/Agents/StatusReducer.swift:79–82

Any Notification whose message contains "waiting" or "idle" is demoted to an idle nudge — a permission prompt for a tool whose description contains either word silently loses .needsAttention, the feature's headline event. Conversely, if Claude's nudge wording changes or is localized, the stuck-"needs you" bug the comment describes returns. Flagged independently by two review passes; deserves a structured signal or at least anchored matching.

MediumTwo Claude sessions in one cwd flap and fire spurious ended events
ProcessScanner.swift:17–37; SessionReconciler.swift:56–71; ClaudeCodeProvider.swift:135–138, 209

The scanner dedups by cwd and attributes the pid to whichever transcript is newest, so the scanned sessionId flips between tabs as they alternate writes — each flip drops the other sid (emitting .ended) and later re-adds it with a reset startedAt. The ProcessScanner comment claims hook state keeps distinct sessions visible, but the reconciler purges hook-only sessions after 30s, so an idle second tab vanishes and reappears on every hook. A freshly started claude in a directory with older transcripts is also briefly reported under the previous session's id, prompt, and response.

6. Bugs — UI layer

MediumThe advertised compact→expanded artwork morph is dead code
Notch/Views/MediaPlayerView.swift:56; CompactView.swift:108

The matchedGeometryEffect(id: "artwork") pair can never animate: every collapse resets expandedTab = .home, so at expansion the media tab is never selected — MediaPlayerView mounts only on a later tab click, when CompactView is long unmounted. The namespace plumbed through ExpandedView/NotchRootView does nothing, as does HUDOverlayView.namespace, which is accepted and never read.

MediumFixedExpanded panel side padding compensates with the wrong inset
Notch/Views/ExpandedView.swift:29; NotchShape.swift:35–36; Animations.swift:56–59

The content pads 12 + compactCornerRadius (24pt) on the theory that the blob insets its sides by the corner radius — but with notchWidth > 0, NotchShape's side inset is shoulderInset = (width − notchWidth)/18 ≈ 18.3pt at expanded width. The visible side margin is ~5.7pt against the 12pt bottom margin — the "pinched sides" the padding was written to prevent. The compensation should use NotchMetrics.shoulderInset(width:notchWidth:).

MediumFixedSeek bar snaps back after a scrub
Notch/Views/MediaPlayerView.swift:139–144

onEnded runs onScrub(target); isScrubbing = false synchronously, but the seek is async — the next 0.5s TimelineView tick renders the pre-seek snapshot, so the fill visibly jumps back, then forward when the player reports the new position. Hold the scrub value (or optimistically update the snapshot) until the seek round-trips.

MediumFixedSessions nested more than one level deep silently disappear from the agents list
Notch/Views/Agents/AgentsView.swift:37–47

topLevelSessions excludes any session whose parent is present, and rows are emitted only for top-level sessions plus direct children. A grandchild (a sub-agent spawning its own sub-session, which OpenCode supports) is excluded from the top level and never returned by children(of:) for any rendered row.

8. Architecture flaws

1. The concurrency model is annotation-deep, not enforcement-deep

SWIFT_STRICT_CONCURRENCY: minimal (project.yml:15) means the pervasive @MainActor annotations and MainActor.assumeIsolated hops are unchecked assertions. Three confirmed violations already exist (ScriptingMediaController and AdapterMediaController doing isolated work on GCD queues; BatteryManager's callback pattern diverging from the rest), and AppEnvironment.start()'s assumeIsolated is safe only because AudioHardware happens to dispatch to main — an invariant enforced nowhere. A strict-concurrency migration will surface all of these at once; better to fix them incrementally now, file by file, than under duress later.

2. Lifecycle asymmetry: start() without stop() everywhere

Nearly every long-lived object can start but not cleanly stop: MediaControlling.stop() is a dead protocol requirement, SystemDefinedTap and BatteryManager hold unretained self-pointers in C callbacks with no invalidation, DirectoryWatcher's deinit races its own queue, AgentSocketServer.bind has no double-start guard, and runtime enable/disable of the agents feature is half-implemented (silent no-op on enable, in-flight tasks surviving disable). All of it is "safe because AppEnvironment owns everything for app lifetime" — a single implicit invariant carrying a dozen latent use-after-free and leak traps. Either make the objects genuinely restartable or document and assert the app-lifetime ownership.

3. The event pipeline discards ordering, then trusts timestamps it created

Socket envelopes travel: concurrent read queue → independent unstructured Task hops → ingest-time Date() stamps → a reducer that resolves hook-vs-transcript by comparing those stamps. Each stage is individually reasonable; composed, they mean the system can manufacture evidence that a stale event is the newest. Ordering should be established once, early (serial delivery queue or client sequence numbers), so the reducer's time comparisons mean what they say.

4. Two sources of truth for compact-pill geometry

The AppKit side (HitRegion/NotchLayout, driving click-through) and the SwiftUI side (CompactView's actual layout) compute the pill's size independently, and they already disagree (fixed 18pt vs shoulderInset + 9 padding; time-dependent timer labels; the stale-on-resize click-through region). The pure LayoutSnapshot → HitRegion.rect extraction is good; the missing piece is making SwiftUI consume the same numbers (or report its measured frame back) so the two can't drift, and re-running passthrough on content changes, not just pointer moves.

5. Config-file surgery without a safety contract

AgentConfigInstaller edits a file it doesn't own (~/.claude/settings.json) with a substring marker, no locking, a full pretty-printed rewrite, and a recovery snapshot stored in a directory the user is likely to delete when removing the app. The refuse-to-clobber-unreadable guard and symlink write-through show the right instincts; the remaining edges (sections 2) are all consequences of treating a shared config as an exclusive resource. An exact-match marker, an advisory lock or read-verify-retry, and storing the statusLine snapshot inside settings.json itself (e.g. a notchOriginalStatusLine key) would close them.

6. Composition root undermined by residual singletons

AppEnvironment is a textbook composition root, but init() hardcodes Settings.shared and Haptics.tap reads the global directly, while every manager takes settings by injection. Since Settings(defaults:) is public, a test-constructed Settings and the singleton can diverge. Pass settings into the root and let Haptics take its dependency.

7. Single-slot callbacks as the app-internal event bus

AudioHardware exposes exactly one onChange and one onRouteChange, assigned by different owners; DirectoryWatcher, the providers, and AgentSocketServer follow the same single-closure pattern. Any future second consumer silently steals the slot. The rest of the app is Combine/ObservableObject-driven — publishers would match the house style and remove the clobbering hazard.

8. Dead plumbing is accumulating

renderingActive is write-only (the occlusion-pause feature it implies doesn't exist), MediaControlling.stop() has no caller, SettingRow references a removed feature, collapse(hasCompactContent:) is always true, topRadius is ignored but animatable, the matched-geometry namespace threads through three views to do nothing, and FocusManager.name is never assigned. Individually trivial; collectively they misdescribe the system to the next reader. Worth a dedicated cleanup pass.

9. The riskiest layer is the least tested

The pure-core extraction strategy works — 71 passing tests pin StatusReducer, TranscriptParser, SessionReconciler, the installer, BatteryPolicy, CalendarReminders, and HitRegion. But the stateful orchestration where most of this report's agent-watch bugs live has zero coverage: SocketAgentProvider (the sole path for 3 of 4 agent kinds), ClaudeCodeProvider's debounce/generation/disable races, and AgentManager's routing and pill signature. SocketAgentProvider in particular is @MainActor with injectable closures and no I/O in its ingest path — unit-testable as-is.
